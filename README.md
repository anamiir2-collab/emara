# عِمارة | Emara — نظام إدارة العقارات

تطبيق ويب تقدّمي (PWA) متكامل لإدارة العقارات، يعمل بالكامل في المتصفح بدون أي خادم. مصمّم باللغة العربية RTL بواجهة مستوحاة من تطبيقات الهواتف الحديثة، مع لوحة ألوان أخضر غابي وعاجي دافئ.

> التطبيق للعرض المحلي فقط. لا تُرسل أي بيانات خارج الجهاز.

---

## الميزات الرئيسية

- **إدارة كاملة للعقارات**: المباني، الوحدات، السكان، العقود، الالتزامات.
- **محاسبة دقيقة**: حسابات بالقروش الصحيحة (integer piastres)، تحصيلات كاملة وجزئية، عكس الدفعات مع سجل تدقيق، فصل بين الالتزامات والتحصيلات والمصروفات.
- **الصيانة**: طلبات بأولويات وحالات وتكاليف وفنيين.
- **الإيصالات**: ترقيم تلقائي وطباعة بدون إنشاء معاملات مكررة.
- **التقارير**: كشف per المبنى، ملخص شهري، مستحقات، تصدير CSV متوافق مع Excel للعربية.
- **النسخ الاحتياطي**: JSON كامل مع دمج أو استبدال، مع منع تكرار السجلات المالية عبر البصمات (fingerprints).
- **واتساب**: توليد روابط `wa.me` برسالة قابلة للتعديل قبل الإرسال — لا يُرسل تلقائيًا.
- **بوابة الساكن**: عرض محلي للساكن مع تنبيه واضح بأنها ليست مصادقة آمنة.
- **PWA**: يعمل دون اتصال بعد أول تحميل، قابل للتثبيت على Android و iPhone.
- **RTL وأيقونات SVG**: لا رموز تعبيرية (emoji) في الواجهة الأساسية.

### كيف تتصل الملفات

- `index.html` يحمّل سبع ملفات CSS بالترتيب، ثم `js/app.js` كـ ES module.
- `app.js` يستورد `config.js` و`router.js` و`database.js` و`notifications.js`، ويرسم الـ shell (sidebar/topbar/bottomnav)، ثم يستورد كل وحدة ديناميكيًا عبر `import('./js/modules/<name>.js')` عند تغيّر المسار.
- كل وحدة في `js/modules/` تصدّر `mount(container, ctx)` و`unmount()` اختيارية.
- تستخدم الوحدات `js/ui.js` للعناصر المشتركة، و`js/database.js` للوصول لـ IndexedDB، و`js/ledger.js` للعمليات المالية.
- `js/calculations.js` دوالها نقية (pure) وقابلة للاختبار بمعزل عن DOM وIndexedDB.
- `service-worker.js` يخزّن الـ app shell مؤقتًا ويتجاهل ملفات التصدير/النسخ الاحتياطي.

## التشغيل محليًا

التطبيق يحتاج خادمًا ثابتًا بسيطًا (لا يعمل عبر `file://` بسبب قيود ES modules و service workers). اختر أيًا من:

### باستخدام Python (مدمج في معظم الأنظمة)

```bash
cd emara
python3 -m http.server 8080
```

ثم افتح <http://localhost:8080/> في المتصفح.

### باستخدام Node (npx)

```bash
cd emara
npx serve .         # أو: npx http-server -p 8080
```

### باستخدام VS Code

ثبّت إضافة **Live Server**، ثم انقر بزر الفأرة الأيمن على `index.html` واختر "Open with Live Server".

> على iOS / Android للتطوير اللاسلكي: استخدم خادم HTTPS. الـ service worker يتطلب سياقًا آمنًا (HTTPS أو localhost).

## الرفع إلى GitHub

1. أنشئ مستودعًا جديدًا على GitHub، مثلاً `emara`.
2. من جهازك:
   ```bash
   cd emara
   git init
   git add .
   git commit -m "Initial commit: Emara PWA"
   git branch -M main
   git remote add origin https://github.com/USERNAME/emara.git
   git push -u origin main
   ```
3. لا ترفع ملفات `emara-backup-*.json` (المستثناة في `.gitignore`).

## تفعيل GitHub Pages

1. في صفحة المستودع على GitHub: **Settings → Pages**.
2. تحت **Build and deployment** اختر:
   - **Source**: `Deploy from a branch`
   - **Branch**: `main` / folder: `/root` (جذر المستودع)
3. احفظ. خلال دقائق ستحصل على رابط مثل:
   ```
   https://USERNAME.github.io/emara/
   ```
4. التطبيق يستخدم مسارات نسبة (relative paths) في `index.html` و`manifest.webmanifest` و`service-worker.js`، فيعمل مباشرة تحت المسار الفرعي `/emara/` بدون أي تعديل.

> إذا سمّيت المستودع `<USERNAME>.github.io`، سيعمل التطبيق من جذر النطاق أيضًا دون تغيير.

## تثبيت التطبيق (PWA)

### على Android (Chrome / Edge)

1. افتح رابط GitHub Pages في المتصفح.
2. انتظر حتى يُحمّل التطبيق بالكامل (يكتمل تخزين الـ service worker).
3. من قائمة المتصفح اختر **"تثبيت التطبيق"** / **"Add to Home screen"**.
4. سيظهر رمز "عِمارة" على الشاشة الرئيسية.

### على iPhone (Safari)

1. افتح الرابط في Safari.
2. اضغط زر المشاركة → **"إضافة إلى الشاشكة الرئيسية"**.
3. سيظهر رمز التطبيق. عند فتحه يعمل كتطبيق مستقل (ملء الشاشة، بدون شريط Safari).

> ملاحظة: دعم PWA على iOS محدود مقارنة بـ Android. الـ service workers تعمل لكن قد يُعيد iOS مسحها تحت ضغط التخزين. التحميل الأول يتطلب اتصال إنترنت.

### القيود المعروفة

- التحميل الأول يتطلب إنترنتًا لجلب الموارد وملء الكاش.
- لا يعمل التطبيق عبر `file://` (قيود ES modules و service worker).
- على iOS، قد تُمسح بيانات IndexedDB إذا طالت فترة عدم الاستخدام أو تحت ضغط مساحة التخزين. استخدم النسخ الاحتياطي بانتظام.

## النسخ الاحتياطي والاستعادة

### إنشاء نسخة

1. اذهب إلى **الإعدادات → النسخ الاحتياطي والاستعادة**.
2. اضغط **"تنزيل نسخة احتياطية"**. سيُنزّل ملف `emara-backup-YYYY-MM-DD-HH-MM-SS.json`.
3. يحتوي الملف على كل السجلات والإعدادات. خزّنه في مكان آمن.

### الاستعادة (دمج)

- اضغط **"استيراد نسخة (دمج)"**، اختر الملف.
- ستُضاف السجلات الجديدة فقط. السجلات المالية (دفعات/مصروفات) تُخصم بالبصمة (fingerprint) لمنع التكرار.

### الاستعادة (استبدال)

- اضغط **"استيراد نسخة (استبدال)"**.
- سيتم مسح كل البيانات الحالية ثم استيراد النسخة. **يُنصح بشدة بتنزيل نسخة احتياطية قبل الاستبدال.**

### تصدير CSV

من **الإعدادات → تصدير البيانات** يمكنك تنزيل:
- السكان (CSV)
- التحصيلات (CSV)
- المصروفات (CSV)
- المستحقات per العقد (CSV)

> ملفات CSV تستخدم UTF-8 مع BOM ليعرض Excel الحروف العربية بشكل صحيح.

## المنطق المالي

النظام يفصل بين ثلاثة أنواع من السجلات:

1. **الالتزامات (Obligations)**: المبلغ المتوقع تحصيله (إيجار / اشتراك اتحاد). لا تؤثر على الرصيد النقدي.
2. **التحصيلات (Payments)**: المبلغ الفعلي المحصّل. كل دفعة مرتبطة بـالتزام واحد أو أكثر، ولها بصمة (fingerprint) تمنع التكرار.
3. **المصروفات (Expenses)**: قد تكون **مدفوعة** (تؤثر على الرصيد النقدي) أو **غير مدفوعة** (لا تؤثر).

### المعادلات الأساسية

- **المستحق = إجمالي الالتزامات − إجمالي التحصيلات السارية**
- **الرصيد النقدي = رصيد افتتاحي + تحصيلات سارية − مصروفات مدفوعة**
- المصروفات غير المدفوعة **لا تُخصم** من الرصيد النقدي.
- عكس دفعة (`reverse`) لا يحذفها، بل يضع علامة `reversed=true` مع سبب وتاريخ — يبقى سجل التدقيق سليمًا.

### منع التكرار

- كل دفعة تحصل على `fingerprint` يجمع (الالتزامات، المبلغ، التاريخ، الطريقة). عند محاولة إدخال دفعة بنفس البصمة يُرفض الطلب.
- كل مصروف يحصل على `fingerprint` يجمع (المبنى، المبلغ، التاريخ، التصنيف، الوصف).
- عند استيراد نسخة احتياطية في وضع الدمج، تُفحص البصمات لمنع إدخال دفعات/مصروفات مكررة.

### اختبارات الحسابات

ملف الاختبارات: `tests/financial.test.mjs`. شغّله عبر:

```bash
cd emara
node --test tests/
```

يغطي:
- مجموع الالتزامات والتحصيلات
- حساب المستحق
- الرصيد النقدي مع المصروفات المدفوعة وغير المدفوعة
- تخصيص دفعة على عدة التزامات (oldest-first)
- استبعاد الدفعات الملغاة
- بصمات الدفعات (تطابق واختلاف)
- ملخص شهري

## قيود التخزين المحلي

- **لا مصادقة آمنة**: كل من يفتح المتصفح على الجهاز يرى كل البيانات. لا تستخدم البوابة المحلية كـ multi-tenant على جهاز مشترك.
- **لا تزامن بين الأجهزة**: كل جهاز له قاعدة بيانات IndexedDB مستقلة. النقل اليدوي عبر النسخ الاحتياطي.
- **قد يُمسح التخزين**: المتصفحات قد تحذف بيانات المواقع غير النشطة تحت ضغط المساحة. انسخ احتياطيًا بانتظام.
- **لا نسخ على السحابة**: التطبيق لا يرسل أي بيانات للخارج. ميزة وليست عيبًا للخصوصية، لكن تعني أنك مسؤول عن النسخ.

## المساهمة

التطبيق مفتوح للتعديل. لتوسيعه:

1. أضف وحدة جديدة في `js/modules/<name>.js` تصدّر `mount(container, ctx)` و`unmount()`.
2. أضف مسارًا في `ROUTES` داخل `js/config.js` (التسمية، الأيقونة، اسم الوحدة).
3. أضف الملف إلى `APP_SHELL` في `service-worker.js` إن أردت تخزينه المؤقت.
4. احترم نمط الـ ES modules النسبي (لا bare imports).
